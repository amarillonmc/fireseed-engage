## 数据库应用 / Database Application

全新安装会由 install.php 依序载入核心表与 sql/gameplay_expansion.sql。
Fresh installs load the core schemas and sql/gameplay_expansion.sql through install.php.

现有数据库请先备份，再执行：
Back up an existing database, then run:

mysql -u root -p fireseed_engage < sql/upgrade_20260717_gameplay_expansion.sql

升级脚本为自包含、可重复执行版本，不依赖 mysql 客户端 SOURCE 命令；它会确定性合并旧库重复资源行，并在建立唯一索引前保护既有玩家城市与领地。
The upgrade script is self-contained and rerunnable, does not rely on the mysql-client SOURCE command, deterministically consolidates duplicate legacy resource rows, and protects existing player cities and territory before adding world sites.

安装器的建表和管理员步骤支持中断后安全重跑；同名或同邮箱的冲突账号不会被静默接管。
Installer table creation and administrator provisioning can safely resume after interruption; conflicting username or email ownership is never silently taken over.

最终双轴审查后，无参数 SQL 也统一通过可关闭的预处理语句执行；定时任务、赛季、联盟、经济、任务、地图生成与安装器不再直接调用 mysqli::query。
After the final two-axis review, parameterless SQL also runs through closed prepared statements; cron, season, alliance, economy, progress, map generation, and installation no longer call mysqli::query directly.

## 待产品规则 / Product Rule Still Needed

项目旧规格中的“最后主城失守后成为附属、缴纳大量资源并随机重开”没有给出缴纳数值、附属关系解除条件或重开时保留范围；既有代码也一直禁止主城易主。本次不擅自改变该既有边界。若要启用该流程，需要先确定这些平衡规则。
The legacy project spec does not define the payment amount, vassal-release condition, or retained state for restarting after the last main city falls, while existing code has always excluded main-city capture. This implementation does not invent or silently alter that boundary; those balance rules must be decided before enabling the flow.
